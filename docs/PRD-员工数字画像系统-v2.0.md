### 1.3 实施期变更记录（开发过程中确认的调整）

| 日期 | 变更点 | 原设计 | 调整后 | 原因 |
|---|---|---|---|---|
| 2026-10-14 | **A3 技能标签管理整体取消** | §5.3 预定义模板 + 自定义双层结构，A1 十二卡片含「技能标签」，F14 亮点修改待审，项目总结可关联标签 | **功能下线**：A1 卡片、4 个 API、专项工作提交的「关联技能标签」字段一并移除；A1 卡片减为 **11 张** | 预定义模板表 `portrait_skill_tag_templates` 长期为 **0 行**，下拉框无任何可选内容，员工只能手打自定义标签。手打标签无法做全行统计与画像聚合 —— 而这正是本功能的设计价值。投入产出不成立，故取消而非补数据 |

**取消范围说明**

- 数据库**表结构保留不删**（`portrait_skill_tag_templates` / `portrait_profile_skill_tags`，均为 0 行），如后续重启功能只需重新接线
- A4 兴趣管理**不受影响**，其在独立子表 `portrait_interest_info`，与技能标签无耦合
- `skill_tag_edit` 提交类型**一并下线**（2026-10-14 补做）：从 `VALID_TYPES`、payload 校验分支、3 处白名单 regex 中移除，前端不再提供新建入口。该审批流自设计起就「审批通过但不写任何业务数据」（P5+ 才接入落库），移除不影响数据正确性
- 库中存量 `skill_tag_edit` 提交**原样保留**，仍可正常审批 / 驳回 / 查询
- **响应侧不做类型白名单校验**：创建侧（`SubmissionBase`）严格拦新建，响应侧（`SubmissionInDBBase`）必须容忍历史数据。若两侧用同一套 pattern，任何返回存量记录的列表接口都会因 Pydantic 响应校验抛 `ValidationError` 变成 500
- 前端类型中文案表保留 `skill_tag_edit → 「亮点标签（功能已下线）」` 一条历史项，仅用于让存量提交正常显示（部分渲染点没有 `|| v` 兜底，缺 key 会渲染出 `undefined`）

## 二、产品定位与核心问题

### 2.1 产品定位

员工数字画像系统是面向"集约运营中心（广东）"等内网机构员工的**全维度电子档案 + 动态行为 + 行政台账**一体化平台。它把过去散落在 Excel、纸质表、邮件里的：

- 员工**静态档案**（基础信息、政治面貌、学历、家庭、简历、奖惩、资格、成果、语言）
- 员工**动态行为**（专项工作、活动报名、家访、应急演练、出入境）
- 员工**修改申请**（档案字段修改）

集中到一套**角色化、可检索、可审批、可导出、可审计**的 Web 系统里。

### 2.2 解决的核心问题

| # | 痛点 | 系统如何解决 |
|---|------|------------|
| 1 | 员工档案散落、版本不一致 | 统一建模为 `profiles` 主表 + 10 个子表，所有信息一条记录一次写入 |
| 2 | EHR 号格式不统一 | 全局校验：**恰好 7 位数字**，登录/查询/批量导入处统一拦截 |
| 3 | 手工维护多版本记录效率低 | 子表全部支持**多条、按时间排序**，提供行内新增/修改/删除 |
| 4 | 家访以纸质为主、查找/统计/归档困难 | 完整电子化家访：双阶段表单 + 预览打印 + 批量导出 Excel |
| 5 | 家访对象有组别边界，纸质流程无法校验 | 组长绑定有效组别，后端硬校验 `visited_user.group == viewer.group` |
| 6 | 角色权限混乱 | 三级角色 + 资源级 ACL：本人/本组/全员 |
| 7 | 敏感操作无可追溯 | 全量 `operation_logs`，关键操作 100% 落库 |
| 8 | ~~技能标签无人管理~~ | ~~双层结构：预定义模板 + 员工自定义~~ 🚫 **已取消（2026-10-14，见 §1.3）** |
| 9 | 行政台账（出入境/演练）散落在 Excel | 统一台账页，支持**矩阵视图** + Excel 导出 |
| 10 | 动态申请无统一入口（专项工作、活动） | 统一**动态表单模块** + 我的提交列表 |
| 11 | 审批分散在邮件/口头 | 统一**审批工作台**：批量通过/驳回 + 转交 + 备注 |
| 12 | 1 小时无操作敏感页面挂着 | 后端 JWT 60 分钟过期 + 前端 idle 检测 + 401 自动跳登录 |

## 三、用户与角色模型

### 3.1 角色矩阵

| 角色 | 简称 | 主要场景 | 关键边界 |
|---|---|---|---|
| **普通员工** | `user` | 维护自己档案、提交申请、查看个人记录 | 看不到任何他人数据；不能进家访新建/编辑 |
| **组长** | `leader` | 管理本组成员、新建/编辑本组成员家访 | 跨组 0 权限；未配置组别时连列表都进不去 |
| **管理员** | `admin` | 全员档案、用户管理、审批、出入境/演练台账、家访**只读** | **不可编辑家访**（业务规则：谁做的家访，谁签字） |

### 3.2 EHR 号约定

- **格式**：恰好 7 位数字，前导零不省略（`0000001`）
- **唯一性**：全局唯一，软删除后可被复活复用
- **默认管理员**：`0000001 / 1234567`（首次登录强制改密）

## 五、个人中心（员工自维护）

### 5.1 个人档案首页（A1）

- **页面路径**：员工视图 → 个人档案
- **数据来源**：`GET /api/profile/me`
- **展示结构**：分 **11** 个卡片区块（基础信息 / 政治面貌 / 学历学位 / 家庭关系 / 简历 / 奖惩 / 资格 / 成果 / 语言 / 通讯 / 应急先锋队）
  - ~~技能标签~~ {C}
- **脱敏规则**：身份证号、手机号、出生日期展示为 `138****0001`，鼠标 hover 显示完整
- **快捷操作**：右上角"编辑基本信息"按钮 → 跳 A2

### 5.2 编辑基本信息（A2）

- **提交方式**：单个 PUT，保存无刷新
- **必填项**：姓名、EHR、性别、出生日期
- **受保护字段**：`id_type`、`is_emergency_staff` 不可自改（走 profile_edit 审批流）
- **裁剪说明**（v2.1 用户决定）：**身份证号、手机号、座机、籍贯省市区级联全部不展示不编辑**（涉及隐私字段全裁剪，档案信息以 EHR + 姓名 + 性别 + 出生日期 + 团队岗位为主）

### 5.3 技能标签管理（A3）

> 🚫 **本节已取消（2026-10-14，见 §1.3）**：A3 技能标签功能整体下线。以下内容仅作历史设计留档，**不作为实现依据**。

  - **预定义模板**：管理员在 F1.5 维护，员工在档案下拉里看到全部

## 六、动态表单与提交管理

### 6.1 提交专项工作（B1）

- **业务场景**：员工参与项目后，把"项目工作"登记进个人档案
- **字段**：
  - 项目名（必填，≤ 100 字）
  - 起止时间（必填，start < end）
  - 具体工作内容（必填，富文本，≤ 2000 字）
  - ~~关联技能标签（多选，从 A3 已有标签池里选）~~ 🚫 **已取消（2026-10-14，见 §1.3）**
  - 预估工时（必填，整数小时）
  - **审批人下拉**（必选，列出本组组长 + 管理员）
- **状态机**：`draft → submitted → approved / rejected`
- **审批**：进入 E1 待审批列表，组长/管理员处理

### 6.2 活动申报（B2）— v2.1 重新定义

- **业务场景**：员工**主动申报**自己**已参与过**的活动（运动会获奖、文艺汇演、志愿服务、外部培训等），用于**跟踪加分**与能力记录
- **与 B1 专项工作的区别**：B1 申报"未来要做的项目"；B2 申报"已发生的事"（事后记录+佐证）
- **字段**：活动名、活动时间、活动类型（运动会/文艺/志愿/培训/其他）、主办方、获奖/参与情况、内容描述、可附佐证材料
- **审批**：**走审批流**（与 B1 同链路），由管理员最终审核；通过后落入个人档案"活动记录"子表
- **状态机**：`draft → submitted → approved/rejected`（v2.0 暂不实现 draft 暂存）

### 6.3 我的提交列表（B3）

- **Tab**：全部 / 草稿 / 审批中 / 已通过 / 已驳回
- **筛选**：提交时间区间、类型（专项/活动）
- **操作**：草稿可编辑/删除；审批中可撤回；已通过/已驳回可看详情

### 6.4 提交详情页（B4）

- **展示**：完整表单内容 + 审批流（节点、时间、审批人、意见）
- **操作**：草稿状态可编辑；驳回后可"重新提交"（生成新实例，旧记录保留）

## 七、家访记录（组长 + 管理员）

### 7.1 组长填家访表单（C1）

- **Step 1：家访明细**（基于实际业务表格"家访明细表"v2.1 校准）

  - 是否已家访 Switch
  - 扫描件上传（PDF/JPG，≤ 5MB，必填，状态记"已提交/未提交"）
  - 备注（自由文本）

## 十四、数据库模型

### 14.1 ER 概览

```
users                       用户主表（EHR 号、姓名、组别、角色、密码哈希、是否禁用、软删时间）
└── profile (1:1)           基础信息
    ├── political_info (1:N)  政治面貌
    ├── education_info (1:N)  学历学位
    ├── family_info (1:N)     家庭关系
    ├── resume_info (1:N)     简历
    ├── reward_info (1:N)     奖惩
    ├── qualification_info(1:N) 外部资格
    ├── achievement_info (1:N)  专业成果
    ├── language_info (1:N)   语言能力
    ├── interest_info (1:N)   兴趣爱好（v2 新增）
    ├── award_info (1:N)      获奖信息（v2 新增）
    ├── contact_info (1:1)    通讯
    └── profile_skill_tags(N:M) → skill_tag_templates

home_visit_records           家访记录（v2 扩展双人员家访 + 扫描件）
group_transfer_history       组员调换历史（v2 新增）

submission_records           通用提交记录（v2 新增：专项工作/活动报名）
submission_approvals         审批流节点（v2 新增）

drill_records                消防演练登记（v2 新增）
drill_participants           演练参与人员（v2 新增）
entry_exit_records           出入境台账（v2 新增）
training_records             培训记录（v2 预留）

operation_logs               操作日志
```

### 14.2 关键设计约束

- **EHR 号全局唯一**：VARCHAR(7)，CHECK 约束 `LENGTH(ehr_no) = 7 AND ehr_no GLOB '[0-9]*'`
- **软删除**：所有表加 `deleted_at`，查询统一带 `deleted_at IS NULL`
- **时间字段**：统一 `DATETIME`，按业务时区（北京时间 UTC+8）写入
- **敏感字段脱敏**：身份证号、手机号、座机在 API 返回时按角色脱敏

## 十六、关键业务流程

### 16.1 首次使用流程

```
管理员跑 init_db.py
   → 创建默认管理员 EHR=0000001 / pwd=1234567
   → 登录
   → 批量导入用户（EHR 必填、姓名/组别必填）
   → 通知员工用 EHR + 默认密码首次登录
   → 员工到"我的档案"自行改密 + 补全档案
```

### 16.2 员工提交专项工作流程

```
员工登录 → 提交专项工作 → 填写表单 + 选审批人 → 提交
   → 状态：审批中（进入 B3 我的提交列表 + 审批人 E1 待审批）
   → 审批人（组长或管理员）→ E2 详情 → 通过 / 驳回 / 转交
   → 状态变更：B3 列表更新 + 站内信通知
   → 已通过 → 自动写入"项目总结"子表
```

### 16.3 组长做家访流程

```
组长登录 → 家访列表 → 新建家访记录
   → Step 1: 选本组组员（自动从档案带出岗位/电话/家属）
   → 填写家访年度/时间/方式/地址/双人家访人员/是否已家访/上传扫描件
   → Step 2: 团队名称（自动 = 审核处理团队）
   → 预填"七点模板"，实地家访时填入实际反馈
   → 提交
   → 列表/详情中可一键预览打印 / 导出 PDF
   → 每月/每季批量导出 Excel 给部门归档
   → 管理员在 E1 待审批 → 通过（正式归档）
```

### 16.4 管理员登记消防演练流程

```
管理员 → 消防演练 → 演练登记
   → 填写活动信息（日期/类型/地点/时长）
   → 快速勾选参与人员（支持团队筛选 + 全员/清空）
   → 提交
   → 自动更新到 F4 演练矩阵
   → 员工 D2 个人档案展示页可见
```

### 16.5 审计追溯流程

```
管理员 → 操作日志
   → 按时间倒序查看
   → 筛某用户、筛某动作、筛某资源
   → 异常操作可直接定位 IP、操作时间、详情描述
   → 关键操作（登录、改密、用户增删改、批量导入、家访 CRUD、审批）100% 落库
```

### 17.3 安全设计

| 维度 | 措施 |
|---|---|
| 密码存储 | PBKDF2-HMAC-SHA256 + 32 字节随机盐 + 10 万次迭代，存 `salt:hash` 形式 |
| Token | HS256 JWT，60 分钟过期；`Authorization: Bearer …` 头 |
| 密码字段 | 后端返回 `UserResponse` 不含 `password_hash` |
| 软删除 | 用户 `deleted_at`；查询统一带 `deleted_at IS NULL` |
| 角色守护 | `get_current_admin` 装饰器、路由级 `current_user.role` 校验 |
| 跨组隔离 | 组长列表/查看/编辑/删除均以 `group_name` 强校验 |
| 数据校验 | EHR、身份证（含校验码）、手机号、座机、日期全部后端强校验 |
| 自动登出 | 前端 60 分钟 idle + 后端 60 分钟 token 过期双重保险 |
| 操作审计 | 所有写操作落 `operation_logs` |
