## 二、产品定位与核心问题

### 2.1 产品定位

员工数字画像系统是面向"集约运营中心（广东）"等内网机构员工的**全维度电子档案 + 动态行为 + 行政台账**一体化平台。它把过去散落在 Excel、纸质表、邮件里的：

- 员工**静态档案**（基础信息、政治面貌、学历、家庭、简历、奖惩、资格、成果、语言、技能标签）
- 员工**动态行为**（专项工作、活动报名、家访、应急演练、出入境）
- 员工**修改申请**（档案字段修改、亮点标签新增）

集中到一套**角色化、可检索、可审批、可导出、可审计**的 Web 系统里。

### 2.2 解决的核心问题

| # | 痛点 | 系统如何解决 |
|---|------|------------|
| 1 | 员工档案散落、版本不一致 | 统一建模为 `profiles` 主表 + 10 个子表，所有信息一条记录一次写入 |
| 2 | EHR 号格式不统一 | 全局校验：**恰好 7 位数字**，登录/查询/批量导入处统一拦截 |
| 3 | 手工维护多版本记录效率低 | 子表全部支持**多条、按时间排序**，提供行内新增/修改/删除 |
| 4 | 家访以纸质为主、查找/统计/归档困难 | 完整电子化家访：双阶段表单 + 预览打印 + 批量导出 Excel |
| 5 | 家访对象有组别边界，纸质流程无法校验 | 组长绑定有效组别，后端硬校验 `visited_user.group == viewer.group` |
| 6 | 角色权限混乱 | 三级角色 + 资源级 ACL：本人/本组/全员 |
| 7 | 敏感操作无可追溯 | 全量 `operation_logs`，关键操作 100% 落库 |
| 8 | 技能标签无人管理 | 双层结构：**预定义模板 + 员工自定义**，并防重复 |
| 9 | 行政台账（出入境/演练）散落在 Excel | 统一台账页，支持**矩阵视图** + Excel 导出 |
| 10 | 动态申请无统一入口（专项工作、活动） | 统一**动态表单模块** + 我的提交列表 |
| 11 | 审批分散在邮件/口头 | 统一**审批工作台**：批量通过/驳回 + 转交 + 备注 |
| 12 | 1 小时无操作敏感页面挂着 | 后端 JWT 60 分钟过期 + 前端 idle 检测 + 401 自动跳登录 |

## 三、用户与角色模型

### 3.1 角色矩阵

| 角色 | 简称 | 主要场景 | 关键边界 |
|---|---|---|---|
| **普通员工** | `user` | 维护自己档案、提交申请、查看个人记录 | 看不到任何他人数据；不能进家访新建/编辑 |
| **组长** | `leader` | 管理本组成员、新建/编辑本组成员家访 | 跨组 0 权限；未配置组别时连列表都进不去 |
| **管理员** | `admin` | 全员档案、用户管理、审批、出入境/演练台账、家访**只读** | **不可编辑家访**（业务规则：谁做的家访，谁签字） |

### 3.2 EHR 号约定

- **格式**：恰好 7 位数字，前导零不省略（`0000001`）
- **唯一性**：全局唯一，软删除后可被复活复用
- **默认管理员**：`0000001 / 1234567`（首次登录强制改密）

## 五、个人中心（员工自维护）

### 5.1 个人档案首页（A1）

- **页面路径**：员工视图 → 个人档案
- **数据来源**：`GET /api/profile/me`
- **展示结构**：分 12 个卡片区块（基础信息 / 政治面貌 / 学历学位 / 家庭关系 / 简历 / 奖惩 / 资格 / 成果 / 语言 / 通讯 / 技能标签 / 应急先锋队）
- **脱敏规则**：身份证号、手机号、出生日期展示为 `138****0001`，鼠标 hover 显示完整
- **快捷操作**：右上角"编辑基本信息"按钮 → 跳 A2

### 5.2 编辑基本信息（A2）

- **提交方式**：单个 PUT，保存无刷新
- **必填项**：姓名、EHR、性别、出生日期
- **特殊控件**：籍贯/出生地/户籍地**省市区三级级联**
- **校验**：身份证号 18 位 + 校验码、手机号 1[3-9]xxxxxxxxx、座机 7-20 位、日期合法

### 5.3 技能标签管理（A3）

- **双层结构**：
  - **预定义模板**：管理员在 F1.5 维护，员工在档案下拉里看到全部
  - **自定义**：员工可手动输入任意标签，**大小写去重**
- **防重复**：添加时实时校验，已存在的提示"该标签已存在"
- **关联项目**：技能标签可在项目总结里关联（多选）

### 5.4 兴趣爱好（A4）

- **独立子表**：与技能标签分离（业务上兴趣≠技能）
- **字段**：兴趣名 + 熟练度（入门/熟练/精通）
- **使用场景**：智能筛选 - 活动选人

### 5.5 获奖信息（A5）

- **字段**：奖项名、颁奖机构、获奖时间、级别（国家级/省部级/行级）
- **排序**：按获奖时间倒序

## 六、动态表单与提交管理

### 6.1 提交专项工作（B1）

- **业务场景**：员工参与项目后，把"项目工作"登记进个人档案
- **字段**：
  - 项目名（必填，≤ 100 字）
  - 起止时间（必填，start < end）
  - 具体工作内容（必填，富文本，≤ 2000 字）
  - 关联技能标签（多选，从 A3 已有标签池里选）
  - 预估工时（必填，整数小时）
  - **审批人下拉**（必选，列出本组组长 + 管理员）
- **状态机**：`draft → submitted → approved / rejected`
- **审批**：进入 E1 待审批列表，组长/管理员处理

### 6.2 活动报名（B2）

- **业务场景**：行内活动报名（运动会、文艺汇演、志愿服务等）
- **字段**：活动名、活动时间、报名原因、是否可参加排练
- **特殊**：活动列表管理员维护，员工报名时只看到**未截止的活动**

### 6.3 我的提交列表（B3）

- **Tab**：全部 / 草稿 / 审批中 / 已通过 / 已驳回
- **筛选**：提交时间区间、类型（专项/活动）
- **操作**：草稿可编辑/删除；审批中可撤回；已通过/已驳回可看详情

### 6.4 提交详情页（B4）

- **展示**：完整表单内容 + 审批流（节点、时间、审批人、意见）
- **操作**：草稿状态可编辑；驳回后可"重新提交"（生成新实例，旧记录保留）

## 七、家访记录（组长 + 管理员）

### 7.1 组长填家访表单（C1）

- **Step 1：家访明细**
  - 被家访人下拉（**仅本组成员**）
  - 选择被家访人后**自动从档案回填**：岗位、移动电话、家属姓名/关系/工作单位
  - 家访年度（近 10 年下拉）、家访时间、家访方式（线上/线下）、家访地址
  - **双人家访人员**：必填 2 人（组长 + 同组另一成员）
  - 是否已家访 Switch
  - 扫描件上传（PDF/JPG，≤ 5MB）
- **Step 2：家访记录表**
  - 团队名称固定"审核处理团队"（前端 disabled、后端校验）
  - 家访日期、地址、手机号、家庭电话
  - 家属 1 / 家属 2 各 4 字段
  - 员工家庭情况及家属反馈意见（TextArea，**预填七点模板**）

### 7.2 家访记录列表（C2）

- **筛选**：被家访人 EHR、家访年度、家访方式、是否已家访
- **矩阵视图**：切换到矩阵 Tab，按"组 × 年份"展示，单元格颜色编码（已家访绿/未家访黄）
- **导出**：勾选或不勾选都支持，输出 `家访明细表_YYYY-MM-DD_HHmm.xlsx`

### 7.3 家访详情（C3）

- **卡片式 Descriptions**：家访明细 + 家访记录表两段
- **按钮**：预览打印 / 导出 PDF / 编辑（限组长）
- **PDF 文件名**：`家访记录_姓名_日期.pdf`
- **预览打印**：弹窗还原纸质表格，调用 `window.print()`

  - 培训记录（按时间倒序）
- **只读**：员工只读，管理员可编辑

## 九、审批工作台（共用）

### 9.1 待审批列表（E1）

- **入口**：管理员视图 → 审批工作台 → 待审批 Tab
- **聚合**：4 类审批（专项工作/家访/档案修改/亮点修改）合并到统一列表
- **展示列**：编号、类型 Badge、申请人、标题、提交时间、等待天数、状态 Badge
- **批量操作**：
  - 勾选 → 顶部出现批量条"已选 N 项"
  - 批量通过 / 批量驳回 / 批量转交
- **筛选**：类型（多选）、状态（待审批/已通过/已驳回）、时间区间、申请人

### 9.2 审批详情（E2）

- **展示**：申请详情卡片 + 申请人档案摘要 + 历史审批记录
- **操作**：
  - **通过**（绿色按钮，二次确认）
  - **驳回**（红色按钮，**必须填备注**）
  - **转交他人**（选其他审批人，备注转交原因）
- **审批意见**：必填 TextArea，最多 500 字
- **状态变更**：触发 `operation_logs` 记录 + 通知申请人（站内信）

### 9.3 历史审批记录（E3）

- **时间倒序**，默认显示近 30 天
- **筛选**：类型、结果、审批人、时间区间
- **导出**：支持 Excel 导出（管理员导出全量）

## 十一、组员管理（组长专属）

### 11.1 组员花名册（G1）

- **列表**：当前组员 + 状态徽标（在岗/休假/借调）
- **筛选**：姓名、EHR、状态
- **操作**：查看档案、查看家访、发起家访

### 11.2 新增 / 编辑组员（G2/G3）

- **新增**：实际是触发管理员"用户换组"流程（把现有用户换到本组）
- **编辑**：仅可编辑本组员的**联系信息**（手机/邮箱/家庭地址），其他字段只能查看

### 11.3 全员档案（G4）

- **只读概览**：跨组查看基本档案（姓名/组别/岗位/技能标签）
- **限制**：其他组的详情页跳转会被 403 拦截

### 11.4 组员调换历史（G7）

- **字段**：调出时间、调入时间、原组、目标组、操作人
- **业务价值**：让组长了解人员流动，避免"老员工不知道新员工是哪天来的"

### 11.5 我的家访（G8）

- **筛选**：仅显示**当前登录组长**作为家访人之一的记录
- **用途**：组长自查自己做过哪些家访

## 十二、档案/亮点修改与用户管理（管理员）

### 12.1 档案修改待审（F13）

- **来源**：员工 A2 提交修改，或组长 G3 替组员提交修改
- **展示**：编号、类型 Badge（档案/亮点）、申请人、修改对象、修改字段、**原值（删除线）**、**新值（绿色）**、提交时间
- **审批**：进入 E2 详情页

### 12.2 亮点修改待审（F14）

- **场景**：员工想新增/删除技能/兴趣标签，但**超出允许范围**（如新增了高敏感标签）
- **业务规则**：
  - 普通标签（技术类、文艺类）→ 不需要审批，员工自助即可
  - **高敏感标签**（涉密类、政治类）→ 必须管理员审批

### 12.3 用户花名册（F15）

- **顶部统计**：总用户数、已激活、未激活、已禁用
- **筛选**：姓名/EHR、团队、状态
- **操作**：编辑（改姓名/组别/角色/启用禁用）、禁用（软删）、重置密码、换组

### 12.4 用户换组（F16）

- **两种模式**：
  - 单人换组：搜姓名/EHR → 选目标组 → 填原因
  - 批量换组：Excel 上传，列：EHR、新组别、原因
- **业务校验**：换组后该员工的"组员调换历史"自动写入新记录

## 十四、数据库模型

### 14.1 ER 概览

```
users                       用户主表（EHR 号、姓名、组别、角色、密码哈希、是否禁用、软删时间）
└── profile (1:1)           基础信息
    ├── political_info (1:N)  政治面貌
    ├── education_info (1:N)  学历学位
    ├── family_info (1:N)     家庭关系
    ├── resume_info (1:N)     简历
    ├── reward_info (1:N)     奖惩
    ├── qualification_info(1:N) 外部资格
    ├── achievement_info (1:N)  专业成果
    ├── language_info (1:N)   语言能力
    ├── interest_info (1:N)   兴趣爱好（v2 新增）
    ├── award_info (1:N)      获奖信息（v2 新增）
    ├── contact_info (1:1)    通讯
    └── profile_skill_tags(N:M) → skill_tag_templates

home_visit_records           家访记录（v2 扩展双人员家访 + 扫描件）
group_transfer_history       组员调换历史（v2 新增）

submission_records           通用提交记录（v2 新增：专项工作/活动报名）
submission_approvals         审批流节点（v2 新增）

drill_records                消防演练登记（v2 新增）
drill_participants           演练参与人员（v2 新增）
entry_exit_records           出入境台账（v2 新增）
training_records             培训记录（v2 预留）

operation_logs               操作日志
```

### 14.2 关键设计约束

- **EHR 号全局唯一**：VARCHAR(7)，CHECK 约束 `LENGTH(ehr_no) = 7 AND ehr_no GLOB '[0-9]*'`
- **软删除**：所有表加 `deleted_at`，查询统一带 `deleted_at IS NULL`
- **时间字段**：统一 `DATETIME`，按业务时区（北京时间 UTC+8）写入
- **敏感字段脱敏**：身份证号、手机号、座机在 API 返回时按角色脱敏

## 十六、关键业务流程

### 16.1 首次使用流程

```
管理员跑 init_db.py
   → 创建默认管理员 EHR=0000001 / pwd=1234567
   → 登录
   → 批量导入用户（EHR 必填、姓名/组别必填）
   → 通知员工用 EHR + 默认密码首次登录
   → 员工到"我的档案"自行改密 + 补全档案
```

### 16.2 员工提交专项工作流程

```
员工登录 → 提交专项工作 → 填写表单 + 选审批人 → 提交
   → 状态：审批中（进入 B3 我的提交列表 + 审批人 E1 待审批）
   → 审批人（组长或管理员）→ E2 详情 → 通过 / 驳回 / 转交
   → 状态变更：B3 列表更新 + 站内信通知
   → 已通过 → 自动写入"项目总结"子表
```

### 16.3 组长做家访流程

```
组长登录 → 家访列表 → 新建家访记录
   → Step 1: 选本组组员（自动从档案带出岗位/电话/家属）
   → 填写家访年度/时间/方式/地址/双人家访人员/是否已家访/上传扫描件
   → Step 2: 团队名称（自动 = 审核处理团队）
   → 预填"七点模板"，实地家访时填入实际反馈
   → 提交
   → 列表/详情中可一键预览打印 / 导出 PDF
   → 每月/每季批量导出 Excel 给部门归档
   → 管理员在 E1 待审批 → 通过（正式归档）
```

### 16.4 管理员登记消防演练流程

```
管理员 → 消防演练 → 演练登记
   → 填写活动信息（日期/类型/地点/时长）
   → 快速勾选参与人员（支持团队筛选 + 全员/清空）
   → 提交
   → 自动更新到 F4 演练矩阵
   → 员工 D2 个人档案展示页可见
```

### 16.5 审计追溯流程

```
管理员 → 操作日志
   → 按时间倒序查看
   → 筛某用户、筛某动作、筛某资源
   → 异常操作可直接定位 IP、操作时间、详情描述
   → 关键操作（登录、改密、用户增删改、批量导入、家访 CRUD、审批）100% 落库
```

### 17.3 安全设计

| 维度 | 措施 |
|---|---|
| 密码存储 | PBKDF2-HMAC-SHA256 + 32 字节随机盐 + 10 万次迭代，存 `salt:hash` 形式 |
| Token | HS256 JWT，60 分钟过期；`Authorization: Bearer …` 头 |
| 密码字段 | 后端返回 `UserResponse` 不含 `password_hash` |
| 软删除 | 用户 `deleted_at`；查询统一带 `deleted_at IS NULL` |
| 角色守护 | `get_current_admin` 装饰器、路由级 `current_user.role` 校验 |
| 跨组隔离 | 组长列表/查看/编辑/删除均以 `group_name` 强校验 |
| 数据校验 | EHR、身份证（含校验码）、手机号、座机、日期全部后端强校验 |
| 自动登出 | 前端 60 分钟 idle + 后端 60 分钟 token 过期双重保险 |
| 操作审计 | 所有写操作落 `operation_logs` |

### 17.4 接入台账系统（阶段 1 启动中）

详见 `docs/数字画像接入台账方案讨论稿.md`。**核心决策**：
- 以台账项目为底座，数字画像作为其业务模块
- 复用台账的 Casbin 权限、Workflow 引擎、动态字段模型
- **不**共用三系统 users 表，由台账统一管用户
