### 决策 1 · 组长以什么标识为准？→ **A：启用 `teams.leader_id`**

**要解决什么**：代码里"组长 ≡ `users.team_id` 非空"——**任何员工只要被分了个组，就自动获得组长权限**（能看本组所有人档案、能建家访、能审批）。这是审计报告 §1.1 里 8 项功能权限过宽的共同根因。

**已存在的字段**：`teams.leader_id`（`app/models/team.py:15`，`ForeignKey("users.id")`），建表时就有，**代码里一次都没用过**，当前全是 NULL。

**做法**：
- 组长判据从 `viewer.team_id is not None` 改成 `viewer.id == team.leader_id`
- 组表里的 `leader_id` 指向本组的某个人；谁被指向谁是组长
- 一组一个组长，组长身份跟着他所在的组走

**开发要做**：

| # | 事项 | 说明 |
|---|---|---|
| 1 | 新增统一判据函数 | 现有 8 个 service 各自抄了一遍 `is_superuser` + `team_id`，收口成一个函数。审计 §6.1 已登记这是系统性问题 |
| 2 | 替换 8 处调用点 | profile / home_visit / entry_exit / drill / training / group_transfer / submission / files |
| 3 | 管理界面：设置组长 | 管理员能把本组某人设为组长 / 取消 |
| 4 | 历史数据处理 | 现有各组 `leader_id` 全是 NULL，需要一次性指定每组的组长 |
| 5 | **修测试** | 现有测试用 `team_id=None` 代表普通员工、带 team_id 代表组长，判据一改这些用例**集体失效**，必须同步改 |

> ⚠️ 第 5 条容易被忽略：`tests/portrait/test_home_visit_f11_f12.py` 的 `leader` / `member` 固件都是**有 team_id 的**，改完后两人都变普通员工，15 条用例会集体变红。改判据和改测试必须同一次做完。

### 决策 2 · 员工导入模板 + 初始密码 → **A：管理员在 Excel 里逐个填**

**已确定的前提**：画像将来在内网**单独装一套**，不与台账共用数据库；用户由**管理员批量导入**。

**导入模板 4 列**（全部必填）：

| 列 | 说明 |
|---|---|
| EHR 号 | 7 位数字，唯一标识 |
| 姓名 | 与系统已有姓名不一致时整行失败 |
| 组别 | 按组名匹配，匹配不到整行失败 |
| 初始密码 | **管理员自己填**，见下方复杂度规则 |

**初始密码复杂度规则**（三条硬性，缺一不可）：
- 必须含**大写字母**（A-Z）
- 必须含**小写字母**（a-z）
- 必须含**数字**（0-9）
- 必须含**特殊字符**（如 `!@#$%^&*` 等非字母数字）
- **长度 ≥ 8 位**

**校验失败的处理**：不合规**整行失败**，不静默跳过。失败明细里写清楚是哪个人的哪一列不合规。

> **可复用**：`portrait_user_metadata.is_first_login`（首登强制改密）字段和逻辑**已实现**（`auth_service.py:23`），所有导入的用户首登必须改密，不改不放行。

**PRD 需同步**：PRD `:581` 只写了「EHR 必填、姓名/组别必填」，**没有初始密码这一列**，也没有复杂度规则。这条决策要回写进 PRD §16.1。
