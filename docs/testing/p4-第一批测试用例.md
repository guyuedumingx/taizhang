## 二、测试过程中发现的问题

### 发现 1（重要）：casbin enforcer 单例不重载策略

`app/services/casbin_service.py` 的 enforcer 为进程级单例，仅在首次使用时从 DB 加载策略。
**后端进程启动之后由外部脚本写入的 g/p 规则（如 add_role_for_user）对运行中的服务不可见，需重启后才生效**（A7 首次运行为 403，重启后端后为 200，DB 数据未变）。

影响面：
- 单进程部署下，通过角色管理界面做的变更走同一 enforcer（即时生效），不受影响；
- 脚本/种子工具在服务运行期间写策略 → 不生效；多进程部署（多 worker）下任意一 worker 的变更对其他 worker 不可见。

建议（backlog）：enforcer 增加 `load_policy()` 定时重载，或提供管理端"重载权限"接口；多 worker 部署前必须解决。

### 发现 2（重要）：api_tests 直接读写 dev 库（taizhang.db）

`tests/api_tests` 的 conftest 未做数据库隔离，测试过程中会 drop/clear **开发库**的数据
（本次跑回归后，种子用户被替换为 34 个随机测试用户、portrait 表数据被清空）。
services_tests / db_tests 使用独立 test_services.db，无此问题。

建议（backlog）：为 api_tests 增加独立 SQLite 文件或内存库 + 依赖覆盖（get_db），与生产库隔离。
