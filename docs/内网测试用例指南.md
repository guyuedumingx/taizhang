## 一、部署（内网环境准备）

系统要求：Python 3.11+、Node.js 18+。依赖需从内网 pip / npm 私有源安装（包内不含）。

### 1.1 后端

```bash
cd backend
python -m venv venv
source venv/bin/activate          # Windows: venv\Scripts\activate
pip install -r requirements.txt   # 内网源: pip install -i http://<内网pip源>/simple -r requirements.txt
```

> 包内**不含** `.env` 与 `.db` 文件。先自建 `backend/.env`（模板见下），数据库二选一：

| 方式 | .env 配置 | 初始化步骤（backend 目录下依次执行） |
|------|------|------|
| **SQLite（推荐先用这个）** | `DATABASE_TYPE=sqlite` | ① `python init_db.py`（建表 + 超管 admin）→ ② `python create_test_user.py`（超管 testuser）→ ③ `python scripts/seed_special_ledger_data.py`（模板「特殊业务台账」+ 56 条台账，幂等） |
| **Oracle（内网真实库）** | `DATABASE_TYPE=oracle` + 填连接五项 | 已有老库：先跑 §四 迁移脚本加 `imported_by_id`/`import_batch_id` 两列；空库：同 SQLite 三步 + §四 索引脚本 |

`backend/.env` 模板（`SECRET_KEY` 用 `python -c "import secrets; print(secrets.token_urlsafe(32))"` 生成；连接池等其余参数有默认值，可不配）：

```ini
DATABASE_TYPE=sqlite
# 切 Oracle 时改为 oracle 并填写：
ORACLE_USER=taizhang
ORACLE_PASSWORD=CHANGE_ME
ORACLE_HOST=192.168.0.100
ORACLE_PORT=1521
ORACLE_SERVICE=orcl

SECRET_KEY=<运行上面命令生成的随机串>
ACCESS_TOKEN_EXPIRE_MINUTES=11520

FIRST_SUPERUSER=admin
FIRST_SUPERUSER_PASSWORD=admin123
```

启动（端口 8080，前端代理已指向它）：

```bash
uvicorn app.main:app --host 0.0.0.0 --port 8080
```

验证：`http://<主机>:8080/` 返回 `{"message":"台账管理系统API服务"}`；`/api/v1/docs` 能打开 Swagger。

> SQLite 连接池改造（本分支 `session.py` 改动）：SQLite 走 NullPool、自动剔除 Oracle 专用池参数——若内网此前出现过 SQLite 报 pool 参数错误，本次启动应无此问题（见用例 E6）。

### 1.2 前端

```bash
cd frontend
npm install                       # 内网源: npm install --registry http://<内网npm源>
npm run dev                       # 开发模式，/api 代理到 127.0.0.1:8080
# 或构建后静态部署：
npm run build && npm run preview  # 产物 dist/ 交给 nginx，配置见 docs/developer/environment.md
```

> 包内**不含 dist**（旧构建已过期，必须重新 build）。前端 API 地址是相对路径 `/api/v1`，无硬编码域名。

### 1.3 登录账号

### 模块 D：字段值清洗层（含非人民币识别）（★）

> 上游规格：[特殊栏位处理与填写格式提示方案.md](requirements/特殊栏位处理与填写格式提示方案.md) §3.1；规则链配置在 `backend/field_normalizers.json`。

| # | 用例 | 步骤 | 预期 |
|---|------|------|------|
| D1 | 大写金额文法 ★ | 造台账金额分别填：`拾伍元`、`壹佰零伍元`、`柒角伍分`、`壹仟元整` 等（方案 §3.1.1 的 11 个样例） | 依次清洗为 15、105、0.75、1000…；全部不进可疑清单 |
| D2 | 乱填模式 ★ | 依次造：`1,234,567.89`（千分位）、`¥500`（货币符）、`3万`、`5k`（单位词）、`约2000元`（修饰词）、`无`/`没有`（语义空值→0）、全角 `１０００`、会计负数红字形式、`1.5亿`（越界） | 千分位/货币符/单位词/修饰词/全角→自动清洗参与汇总；语义空值→0；越界（>1 亿）→可疑不参与汇总 |
| D3 | 非人民币识别 ★ | 金额分别造 `$1000`、`1000美元`、`USD 500`、`€200`、`日元3000` | 全部进可疑清单，原因「非人民币金额」，**不参与金额合计**；对照 `¥1000`、`1000元`、大写金额不受影响 |
| D4 | 落库写原始值 ★ | 导入/录入脏值后查库（或台账详情） | 库内保持原始字符串，清洗只发生在统计/导出展示层 |
