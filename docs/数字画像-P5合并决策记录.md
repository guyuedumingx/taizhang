## 3. 核心决策：字段命名

### 3.1 决策

采纳远程 haha0E 的字段命名风格：
- `profile.ehr_no` ← `User.ehr_id`
- `profile.group_name` ← `User.department`

### 3.2 决策理由（按 Rule 7 暴露冲突 + Rule 4 目标驱动）

| 维度 | 我方 ehr_id/department | 对方 ehr_no/group_name |
|---|---|---|
| 字段命名贴近 | taizhang User 表 | 数字画像 PRD 原版 |
| 前端工作量 | 0（直接绑 User 字段） | 1 层映射（router/service 层做） |
| 测试资产 | 18 pytest | **28 测试 + Playwright E2E + 浏览器冒烟** |
| 前端 MyProfile 质量 | 5 Tabs 简洁版 | **346 行 13 区块 + Anchor 导航**（更接近 PRD §A） |
| 集成指南 §5 雷区合规 | 都通过（10） | 都通过（10） |

**结论**：对方测试资产更大（28+19=47 个 vs 我方 18 个），MyProfile 更接近 PRD。采纳对方命名。

### 3.3 实施成本

- `schemas/profile.py` 中 `ehr_id/department` → `ehr_no/group_name` rename
- `routers/profiles.py` 第 42-46 行 `base["ehr_id"]` / `base["department"]` 调整
- `profile_service.get_full_profile_by_ehr` 第 96-99 行 `profile._ehr_id` / `profile._department` 调整
