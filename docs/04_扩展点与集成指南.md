# 扩展点与集成指南

> 这是**接入数字画像 / 资产系统 / 新模块**时必读的指南。

---

## 1. 接入新系统的两种思路

### 思路 A：作为"业务模块"接入（推荐）
把新功能作为台账的一个业务模块，**复用用户/审批/字段**。

**改造范围**：
- ✅ 用户管理：**完全复用**台账
- ✅ 权限：**完全复用**Casbin
- ✅ 审批：**完全复用**Workflow 引擎
- ✅ 字段：**完全复用**Template + Field 机制
- ⚠️ 业务表：新功能单独建表（不动台账原有表）

**优点**：工期短 60%，用户统一管理
**缺点**：业务表与账务表共库，需 schema 隔离

### 思路 B：完全独立（不推荐）
新系统自己搭一套。

**改造范围**：所有事自己干
**工期**：2-3 个月
**适用**：技术栈不一致 或 政治不可行时

## 2. 接入数字画像必须解决的 5 个冲突

### 冲突 1：密码哈希算法

| 系统 | 算法 | 实现位置 |
|---|---|---|
| **台账** | **bcrypt** | `app/core/security.py:9` `passlib.context.CryptContext(schemes=["bcrypt"])` |
| 数字画像 | PBKDF2-SHA256 | `backend/app/auth.py` |

**对策（3 选 1）**：

1. **统一改 bcrypt**（推荐）：数字画像的 `auth.py` 改用 bcrypt
   - 优点：长期统一
   - 缺点：用户首次登录会失败（除非迁移时重哈希）
2. **统一改 PBKDF2**：台账改 PBKDF2
   - 缺点：台账用户全要重置密码
3. **并存**：识别 hash 前缀分算法
   - 缺点：复杂度高

### 冲突 2：EHR 字段约束

| 系统 | 约束 |
|---|---|
| **台账** | `VARCHAR(7)` + `pattern=r'^\d{7}$'`（7 位数字） |
| 数字画像 | `VARCHAR(50)`（任意字符串） |

**对策**：
- 数字画像侧校验改为 7 位数字
- 迁移数据时截断/补齐/重号处理（**这是个数据清洗任务**）

### 冲突 3：is_active vs is_disabled（语义反转）

| 系统 | True 含义 | False 含义 |
|---|---|---|
| **台账** | 启用 | 禁用 |
| 数字画像 | 禁用 | 启用 |

**对策**：
- 选台账 `is_active` 为标准
- 数字画像代码里把 `is_disabled == False` 改为 `is_active == True`
- SQLAlchemy 模型加 property：
  ```python
  @property
  def is_disabled(self):
      return not self.is_active
  ```
  保持数字画像老代码仍能跑

### 冲突 4：用户角色模型

| 系统 | 角色管理 |
|---|---|
| **台账** | Casbin RBAC（`policy.csv` 动态加载） |
| 数字画像 | `role` 字段（写死 user/admin/leader/superadmin） |

**对策**：
- 选台账 Casbin 为标准
- 数字画像的 `role` 字段废弃
- 角色判断改为：`get_roles_for_user(user.id)`
- 旧代码中的 `if user.role == 'admin'` 改为 `if 'admin' in get_roles_for_user(user.id)`

### 冲突 5：组别/部门字段

| 系统 | 字段名 |
|---|---|
| **台账** | `department` |
| 数字画像 | `group_name` |

**对策**：选台账 `department` 为标准，数字画像 `group_name` 改为 `department`。

## 3. 接入步骤（5 个阶段）

### 阶段 1：用户模型对齐（3-5 天）

**目标**：数字画像用户表对齐台账

| 工作 | 文件 | 备注 |
|---|---|---|
| 1.1 数字画像 `User` 字段重命名 | `digital_portrait/backend/app/models.py` | `ehr_no → ehr_id`, `group_name → department`, `password_hash → hashed_password`, `is_disabled → is_active`（语义反转）, `is_superadmin → is_superuser` |
| 1.2 sed 批量替换引用 | 9 个 routers | 80% 机械替换 |
| 1.3 哈希算法改 bcrypt | `auth.py` | 同步改 register/login/change_password |
| 1.4 加 `team_id` 字段 | `models.py` | 关联 teams.id |
| 1.5 角色判断改 Casbin | 所有 router | 引入台账的 `casbin_service.py` |
| 1.6 数据迁移脚本 | 新增 | 现有用户 → 台账 users 表 |
| 1.7 全量回归 | 跑 5 个 step 套件 | 必须全过 |

**回滚点**：保留原字段 + git revert

### 阶段 2：业务表迁移到台账库（5-7 天）

**目标**：数字画像 30+ 张业务表搬到台账 PostgreSQL/Oracle，独立 schema

| 工作 | 备注 |
|---|---|
| 2.1 建 `digital_portrait` schema | 数据库侧 |
| 2.2 用 alembic 生成数字画像业务表 | 写迁移脚本 |
| 2.3 数据迁移 | SQLite → PostgreSQL |
| 2.4 数字画像 `__tablename__` 加 schema 前缀 | 如 `profiles` → `digital_portrait.profiles` |
| 2.5 全量回归 | 5 个 step 套件 |

### 阶段 3：审批引擎复用（3-5 天）

**目标**：数字画像的审批走台账 Workflow

| 业务 | 对应 Workflow 配置 |
|---|---|
| 专项工作审批 | `Workflow`：submit → leader_review → admin_approve |
| 家访审批 | `Workflow`：submit → leader_review → admin_approve |
| 活动报名 | `Workflow`：submit → leader_review（可能自动通过）|
| 批量导入 | `Workflow`：admin_approve（单节点）|

| 工作 | 文件 |
|---|---|
| 3.1 台账库建 4 个 Workflow 配置 | 通过台账管理后台 |
| 3.2 数字画像写 service 层调用台账工作流 API | `digital_portrait/backend/app/services/workflow.py`（**新增**）|
| 3.3 删除数字画像侧临时审批代码 | 简化 |

### 阶段 4：前端模块集成（5-10 天）

| 工作 | 备注 |
|---|---|
| 4.1 台账 Ant Design 菜单加"数字画像"入口 | `taizhang/frontend/src/App.tsx` 或 router |
| 4.2 数字画像 30+ 页面迁移 | 工作量最大 |
| 4.3 API 客户端配置 | `api.js` 改 baseURL |
| 4.4 视觉统一：自研样式 → Ant Design | 美化 |

### 阶段 5：测试与上线（3-5 天）

| 工作 | 备注 |
|---|---|

## 5. ⚠️ 接入新系统的 7 个雷区

| # | 雷区 | 后果 | 对策 |
|---|---|---|---|
| 1 | **改台账的 Casbin 模型（rbac_model.conf）** | 所有角色权限失效 | 永远不直接改，走 policy.csv |
| 2 | **直接 DROP 现有 ledger 工作流实例** | 历史审批记录丢失 | 永远 soft delete 或迁移到 history_workflow_instances |
| 3 | **把数字画像的字段值塞进 ledger.data JSON** | 失去字段结构化查询能力 | 单独建业务表 |
| 4 | **跨 schema 写事务** | 事务边界跨 schema 不支持 | 用 API + saga 模式或视图同步 |
| 5 | **修改 JWT payload 加自定义字段** | 老 token 全部失效 | 兼容性添加（用 sub 而非自定义） |
| 6 | **修改 approval_status 枚举值** | 老数据无法解析 | 用 migration script 转译 |
| 7 | **绕过 deps.get_current_active_user 直接读 user_id** | 失去权限校验 | 永远走 Depends |

## 7. 接入工作流的最小心智模型

**记住这张图**：

```
                 ┌─────────────────────────┐
                 │   台账统一身份服务        │
                 │                          │
                 │  - users (ehr_id, ...)   │
                 │  - teams / roles         │
                 │  - Casbin RBAC           │
                 │  - JWT (HS256, 8 天)    │
                 └────────┬────────────────┘
                          │
            ┌─────────────┼─────────────┐
            │             │             │
        ┌───▼────┐   ┌────▼────┐   ┌────▼────┐
        │ 账务   │   │ 数字画像 │   │ 资产   │
        │ (现有) │   │ (接入)  │   │ (接入) │
        └────────┘   └─────────┘   └────────┘
        ledger       profile        asset
        template     skill          item
        workflow     home_visit     transfer
                     special_work   safety
                     
        ↓ 共享 ↓
        Workflow / Field / Log / Approvals（统一）
```

**共享的部分**：用户、角色、团队、Casbin、JWT、Workflow 引擎、Field 引擎、Log 引擎
**隔离的部分**：业务表（独立 schema）
