## 1. 用户登录流程

```
[前端]                   [后端]
   │
   ├── POST /api/v1/auth/login ──→ AuthService.authenticate_user()
   │   body: {ehr_id, password}      │
   │                                 ├── SELECT User WHERE ehr_id
   │                                 ├── verify_password()  [bcrypt]
   │                                 ├── check is_active
   │                                 ├── Casbin.get_roles_for_user()
   │                                 ├── 计算 password_expired (90天)
   │                                 ├── get_permissions_for_role()
   │                                 └── create_access_token({sub, roles})
   │   ←── {access_token, user_info, permissions}
   │
   ├── 存 token 到 Zustand store
   │
   ├── 后续请求带 Authorization: Bearer <token>
   │   │
   │   └──→ deps.get_current_user()
   │         ├── jwt.decode()
   │         └── SELECT User WHERE id=token.sub
```

**关键代码**：
- 服务：`app/services/auth_service.py:16` AuthService.authenticate_user
- 密码验证：`app/core/security.py:32` verify_password（bcrypt）
- Token 生成：`app/core/security.py:14` create_access_token
- 依赖注入：`app/core/deps.py:17` get_current_user

**关键规则**：
- 登录用 **ehr_id**（不是 username）
- 密码错误返回 401（不区分"用户不存在"和"密码错误"）
- is_active=False → 401
- 90 天未改密 → password_expired=True

## 2. 台账生命周期

```
[草稿] ──create──> [draft] ──submit──> [pending] ──approve──> [approved]
                          │                  │
                          │                  └──reject──> [rejected]
                          │
                          └──不提交，保持 draft

数据库字段：
  Ledger.status = draft / active / completed
  Ledger.approval_status = pending / approved / rejected
  Ledger.submitted_at / approved_at  (时间戳)
```

### 2.1 创建台账（draft）

```python
# app/crud/crud_ledger.py
CRUDLedger.create(db, obj_in, created_by_id, updated_by_id)
  → 创建 Ledger 记录
  → created_by_id = current_user.id
  → updated_by_id = current_user.id
  → status = 'draft'
  → approval_status = 'pending'（注意，draft 状态但 approval_status 是 pending）
```

### 2.2 提交台账（pending → 触发工作流）

```
POST /ledgers/{id}/submit
  → LedgerService.submit_ledger()
    → 检查 Ledger.template.workflow_id 是否存在
    → CRUDWorkflowInstance.create_with_nodes()
      → 创建 WorkflowInstance(workflow_id, ledger_id, status='active')
      → 为 workflow 每个节点创建 WorkflowInstanceNode
      → 第 1 个节点 status=pending, 其他=approved
      → 设置 current_node_id 为第 1 个节点的实例
      → 如果第 1 个节点有 approver_role，根据角色找审批人
    → 更新 Ledger.submitted_at
    → log_audit(submit)
```

### 2.3 审批通过

```
POST /approvals/{instance_node_id}/approve
  → CRUDWorkflowInstance.approve_current_node()
    → 检查 instance.status == 'active'
    → 检查当前节点 status == 'pending'
    → 追加 approver_actions 记录
    → 如果多审批人 (multi_approve_type='all' 且未全部审批)：
        只记录 action，不推进
    → 否则：
        当前节点 status='approved'
        查 next_workflow_node (order_index + 1)
        如果没有下个节点 或 下个节点是 end 或 is_final=True：
            instance.status='completed'
            instance.completed_at=now
            Ledger.approval_status='approved'
            Ledger.approved_at=now
        否则：
            下一个节点的 WorkflowInstanceNode.status='pending'
            找下一个审批人（role 或指定）
            更新 instance.current_node_id
```

### 2.4 审批驳回

```
POST /approvals/{instance_node_id}/reject
  → CRUDWorkflowInstance.reject_current_node()
    → 当前节点 status='rejected'
    → 如果 workflow_node.reject_to_node_id 有配置：
            跳转到指定节点（instance.current_node_id = reject_node.id）
        否则：
            instance.status='rejected'
            Ledger.approval_status='rejected'
```

**关键代码**：
- `app/crud/crud_workflow_instance.py:103` approve_current_node
- `app/crud/crud_workflow_instance.py:234` reject_current_node
- `app/crud/crud_workflow_instance.py:349` get_user_pending_tasks
- `app/crud/crud_workflow_instance.py:453` add_approver_action

## 3. 工作流配置流程（管理员设置）

```
1. 管理员创建 Workflow
   POST /workflows/  {name, description, is_active}
   → Workflow.id

2. 为 Workflow 添加节点（按 order_index 顺序）
   POST /workflow-nodes/  {workflow_id, name, node_type, order_index, 
                            approver_role_id, is_final, reject_to_node_id,
                            multi_approve_type}
   
   节点类型：
     - start (order_index=1, 自动审批)
     - approval (中间审批)
     - end (is_final=True)
   
   驳回跳转：
     - reject_to_node_id：指向另一个节点 id（驳回到这里）
     - 不设置：驳回即终止

3. 为审批节点添加审批人（多对多）
   POST /workflow-nodes/{id}/approvers  {user_ids: [1, 2, 3]}
   → 写入 workflow_node_approvers 表
   
   多审批模式：
     - multi_approve_type='any'（默认）：任一人审批即通过
     - multi_approve_type='all'：所有人审批才通过

4. 创建 Template 时绑定 Workflow
   POST /templates/  {name, workflow_id, ...}
   → 后续台账 submit 时按这个 workflow 跑
```

## 4. 自动填充流程

```
[用户]                [前端]                    [后端]
   │                    │                          │
   │ 在关键字段输入     │                          │
   │ (例: 身份证号)     │                          │
   ├──────────────────→│                          │
   │                    │ debounce_ms 去抖          │
   │                    │ (避免每个按键都触发)      │
   │                    │                          │
   │                    │ GET /templates/{id}      │
   │                    │ ← {auto_fill_config}     │
   │                    │                          │
   │                    │ 检测 enabled=true        │
   │                    │ + key_field_name 有值    │
   │                    │                          │
   │                    │ POST /auto-fill-external │
   │                    │ {config, value}          │
   │                    │ ────────────────────────→│
   │                    │                          │
   │                    │                          ├→ 查 auto_fill_trigger_configs
   │                    │                          │   WHERE field_name=...
   │                    │                          │
   │                    │                          ├→ HTTP GET/POST 外部 API
   │                    │                          │   (带 headers, retry_times)
   │                    │                          │
   │                    │                          ├→ 按 field_mapping 转换响应
   │                    │                          │
   │                    │ ← {填值数据}              │
   │                    │                          │
   │ ← 字段已自动填充   │                          │
```

**关键配置**（Template.auto_fill_config JSON）：
```json
{
  "enabled": true,
  "key_field_name": "id_card",
  "trigger_on": "blur",
  "debounce_ms": 500,
  "min_field_length": 6,
  "field_mapping": {
    "name": "response.full_name",
    "address": "response.address.full"
  }
}
```

**关键代码**：
- `app/core/auto_fill_trigger_loader.py` - 启动加载配置
- `app/services/auto_fill_external_service.py` - 调用外部 API
- 模型：`app/models/auto_fill_trigger_config.py`

## 5. 日志记录流程

### 5.1 系统操作日志（SystemLog）

```
任意 endpoint 操作
  → service 层调用 LoggerService.log_operation(
       user_id, module, action, resource_type, resource_id,
       level, message, details
    )
  → INSERT INTO system_logs
```

### 5.2 审批审计日志（AuditLog）

```
提交台账 / 审批通过 / 审批驳回
  → log_audit(
       user_id, ledger_id, workflow_instance_id,
       action, status_before, status_after, comment
    )
  → INSERT INTO audit_logs
```

## 6. 权限检查流程（任意操作）

```
请求进来 → endpoint 函数
  → Depends(deps.get_current_active_user)  ← 解析 JWT
  → deps.check_permissions(resource, action, current_user)  ← Casbin 检查
  
  流程：
    1. is_superuser=True → 直接 True
    2. Casbin.enforce(user_id, resource, action) → True/False
  
  任意失败 → 403 Forbidden
```

**Casbin 模型**（`app/core/rbac_model.conf`）：
```
[request_definition]
r = sub, obj, act

[policy_definition]
p = sub, obj, act

[matchers]
m = g(r.sub, p.sub) && r.obj == p.obj && r.act == p.act
```

这是 RBAC with role inheritance。
