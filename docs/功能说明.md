## 二、功能明细

### 2.1 统计分析 → 台账汇总查询

菜单：左侧「统计分析 → 台账汇总查询」（需 `statistics:view`）。

**筛选能力**：
- 模板多选（不选=全部）；仅选 1 个模板时出现「字段筛选」区并附字段列
- 关键词（台账名称/描述模糊）、状态、审批状态、团队（多选）、创建人（多选）、创建时间范围
- 字段筛选按类型渲染：清洗栏位（`field_normalizers.json` 配置的字段）→ 数值区间（走清洗后值）；select → 下拉单选；date → 日期区间；其他 → 包含匹配
- 排序：系统列与字段列均可排序；服务端分页（20/页，可选 10/20/50/100）

**质量报告**（查询后自动显示）：
- 口径：`有效` = 清洗成功且未越界的行数；`自动清洗` = 原始值脏但被规则修复；`可疑` = 修不出/越界/多值，**不参与汇总**
- 测试数据参考值：金额汇总 8,632,650.18、有效 44、自动清洗 38、可疑 12

### 2.2 视图管理（生成器 → 菜单单等条目）

「台账汇总查询」页是**视图生成器**：组合筛选/指标后点「保存视图」命名保存，视图随即作为动态菜单项出现在左侧「统计分析」下（FilterOutlined 图标，悬浮显示保存时间）；点击菜单项进入生成器页并**自动载入筛选、自动执行查询**（URL 形如 `?view=名称`）。生成器页的「⚙」可载入/删除视图，保存同名即覆盖。视图存浏览器 localStorage（key：`taizhang_ledger_query_views`），保存/删除后菜单实时刷新。

### 2.3 字段值清洗层（配置驱动）

- 配置文件：`backend/field_normalizers.json`——当前仅一条：「特殊业务台账 / 金额」规则链：去空白→全角转半角→语义空值(无/没有→0)→大写金额→去货币符→去千分位→提数字→单位换算(万/千/k/W)→范围检查(0~1亿，越界标可疑)；链尾兜底 flag 进可疑清单
- 架构：规则 = `app/services/normalizers/builtin/` 下的插件（`@register` 即插即用）；特殊栏位清单只在这份 JSON 维护；**新增清洗规则两步**：新建规则文件 + JSON 加一行，引擎零改动
- 单测：`tests/services_tests/test_normalizers.py`

### 2.4 权限赋权操作

给某角色开通统计：权限管理界面按「统计分析→查看统计分析」赋权，或直接向 `casbin_rule` 插入：
`p, <角色名>, statistics, view`（当前库中无任何角色拥有此权限，仅超管旁路）。

### 2.5 测试数据

`backend/scripts/seed_special_ledger_data.py`（幂等）：模板「特殊业务台账」+ 56 条台账，覆盖 28 种金额乱填模式（干净/千分位/货币符/单位词/修饰词/语义空值/全角/会计负数/范围/大写金额/越界/无法解析），两个团队维度。重跑会先清理 `TSB2026%` 旧数据。

## 三、已知边界与注意事项

1. **金额清洗上限 1 亿**（来自方案示例配置）：`壹亿零贰拾万`（1.002 亿）会被标可疑——这是 range_check 在起作用，不是解析错误。生产数值边界需业务确认后改 `field_normalizers.json`。
2. 清洗配置按**模板名**匹配，模板改名会导致规则脱钩（需同步改 JSON）。
3. 可疑明细每字段封顶 50 条；导出行数封顶 1 万行。
4. **跑 `tests/db_tests` 会清空开发库**（`tests/db_tests/conftest.py` 对共享库 drop_all）——跑全量 pytest 前先备份 `backend/taizhang.db`；数据可用 `init_db`（注意其 `FIRST_SUPERUSER` 配置缺失会报错）+ `create_test_user.py` + seed 脚本重建。
5. `backend/taizhang.db` 目前被 git 跟踪，测试数据会随提交入库——是否改为 gitignore 需要团队约定。
6. 自动填充（auto-fill）现为「字段名→API」JSON 配置驱动（`auto_fill_triggers.json`），路径 bug 已修，但配置仍是示例地址，生产使用前需配真实 API。
