# 画像分支重构方案

> 适用分支：`feat/security-pbkdf2-60min-idle-first-login`（重构执行分支：`refactor/portrait-refactor`）
> 评审基线：2026-10-20 三轮代码评审（安全核心 / 画像服务 / 模型迁移 / 前端 / 架构专项）
> 执行原则：每阶段独立可合并、可验证、可回滚；删代码优先于搬代码；先稳定后重构。

---

## 一、架构现状判断

整体骨架健康：画像作为自包含模块（`app/portrait/` 四层结构、`portrait_` 表前缀、不改台账表）方向正确；前端按领域分目录 + 全类型化 API 层正确。需要重构的不是目录结构，而是六个架构级问题：

| # | 问题 | 根因 | 代价 |
|---|---|---|---|
| A | 审批三轨并存：台账引擎 + 画像两套手写状态机 + 4 套死模板 + 假实例机制 | `WorkflowInstance.ledger_id` 非空唯一约束把引擎焊死在台账上 | ~300 行重复状态机；转交/角色审批/多级链能力缺席 |
| B | 模块依赖成环：主系统 service 用局部 import 反向引用画像 | 横切关注点放错层（`is_first_login` 安全状态存在画像业务表；组转移审计由核心 service 反调业务模块） | 循环依赖推迟到运行时爆发 |
| C | 横切能力零基础设施：Excel 导入 4 份实现 4 种事务策略、blob 下载 4 份、分页列表 5 份同构、错误消息拼装 48 处 | 前端只有 API 层公共，往后无共享层 | 每加一页再抄一遍；导入丢数据 bug 即复制走样所致 |
| D | 数据演进靠脚本堆：14 个一次性迁移脚本、两处放置、8 个硬编码 DB 路径、顺序零文档 | 从未建立迁移机制（alembic 在 requirements 里未启用） | 新环境部署靠逆向工程 |
| E | 测试无隔离：8/10 画像测试文件直连开发库写真实数据 | 隔离 fixture 在单文件示范过但未推广到 conftest | 无法建立 CI；跑测试污染开发库 |
| F | 安全控制位置错误：强制改密/空闲超时/密码策略仅前端 enforcement | 安全需求被当前端需求实现 | 账户接管链（评审 P0） |

## 二、阶段划分

### Phase 0 — 安全与正确性修复（合并门槛）

不碰架构，修复评审 P0。验收标准 = 以下每条有测试或可复现验证：

1. **服务端强制首次登录改密**：`get_current_user` 拦截 `is_first_login` 用户，仅放行改密/登出/自身信息端点。
2. **登录失败锁定**：同一账号连续失败 N 次锁定 M 分钟（进程内实现，单进程部署下有效）。
3. **SECRET_KEY 启动防护**：检测到默认密钥时拒绝以非调试模式启动，调试模式生成临时随机密钥并告警。
4. **`.env.example` 修正**：`ACCESS_TOKEN_EXPIRE_MINUTES` 示例值 11520（8 天）→ 60。
5. **自我提权修复**：`UserUpdate` 不再继承 `is_superuser/is_active/roles` 等敏感字段；管理员通道走独立 schema。
6. **家访矩阵组长 500 修复**：`home_visit_service.matrix` 的 `in subquery` → 取数后集合判断。
7. **出入境导入循环 rollback 修复**：行级失败不再回滚全部已成功行、成功数与入库一致。
8. **家访列表分页 total 修复**：`total` 用查询基数而非本页条数。
9. **改密端点密码策略后端校验**：与前端规则一致的最小强度校验（长度≥6 纯数字为现状基线，本阶段只做"前后端一致"，强度提升另行立项）。

### Phase 1 — 卫生清理（净删除）

1. **测试隔离推广（提前执行——它是 Phase 0 验证的前提）**：根 `tests/conftest.py` 改为函数级内存库 + 全量建表 + 双点 SessionLocal 替换（复用 `test_home_visit_f11_f12.py` 已验证的模式）。验收：`pytest tests/portrait` 不依赖、不触碰任何 `.db` 文件。
2. `git rm --cached backend/test_services.db`（.gitignore 已有 `backend/*.db`）。
3. 死代码删除：`_can_view_record`、entry_exit `update()` 无效校验块、`routers/portrait.py` 的 `if True else []`、空 `crud/` 目录、死的 `app/portrait/tests/` 目录、`TERMINAL_STATUSES` 死定义。
4. `__import__("datetime")/("math")` 黑魔法 → 正常 import（12 处）。
5. `backend/MIGRATIONS.md`：14 个脚本的执行顺序、幂等性、目标库说明。

### Phase 2 — 审批引擎泛化 + 状态机合并（核心，单独分支执行）

1. `WorkflowInstance` 加 `subject_type + subject_id`；`ledger_id` UNIQUE → `(subject_type, subject_id)` 复合唯一；存量数据迁移为 `subject_type='ledger'`。
2. 引擎内联台账回写抽成注册式回调。
3. 引擎自身债务：approve/reject 权限判定抽 helper；删注释掉的三处死代码；修 `current_node` property 每次新建 engine+Session。
4. 画像 submission/home_visit 委托引擎，删两套状态机 ~300 行；`portrait_approval_records` 降级为审计增强层。
5. 4 套模板转正为真正被实例化。
   验收：全部画像测试走引擎路径通过 + 组长路径测试（现 500 的那条）。

### Phase 3 — 服务层消重（可与 Phase 2 并行）

后端：泛型子表 helper 推广到 1:N（消 5 套 CRUD 三件套 ~230 行）；共享 Excel 导入脚手架（4 归 1，事务策略统一）；两个 sync service 合并公共核。
前端：`ImportResultPanel` 共享组件；统一 `downloadBlob`；状态映射与 `'审核处理团队'` 进 constants；`getApiErrMsg` 收口 48 处；拆 HomeVisits/MyProfile 至 400 行以下。

### Phase 4 — 依赖解环 + 安全状态归位

`is_first_login` 挪回核心用户模型（含数据迁移）；组转移联动从 service 层局部 import 上提到路由层显式编排；删除三处"局部 import 避免循环"补丁。

### Phase 5 — 迁移基础设施

启用 alembic（依赖已在），当前 schema 做 baseline；14 个脚本归档 `legacy/`；幸存脚本统一走 `SessionLocal`。

## 三、明确不做

不换 ORM；不升 Python 大版本；不动台账业务逻辑；不重写前端状态管理；不做微服务拆分；密码强度提升（超过现状基线）另行立项；真滑动会话（refresh token）另行立项——本阶段以 60 分钟短 TTL + 服务端首登拦截为基线。
