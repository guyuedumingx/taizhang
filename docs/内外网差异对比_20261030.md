## 二、内网改动主题分解（120 文件）

- **表名统一加前缀**：`users`→`taizhang_users`、`teams`→`taizhang_teams` 等，外键同步改

- **String 显式长度**：`String`→`String(100/255)`（Oracle 必需，SQLite 可省）

## 四、冲突区与合并路线

- **唯一冲突文件 `.gitignore`**：手工合并即可，无实质冲突。
- **推荐路线**：以 `intranet` 分支为**生产基线**；外网新功能开发完成后，按"适配约定清单"（见下）改造，再经文件通道送入内网验证。不建议把内网 120 文件改动反向合并进 feature 分支（会让外网分支背着 Oracle/行信等内网专属依赖）。

### 外网功能送入内网的适配约定清单（Checklist）

1. 新表/新列：表名加 `taizhang_` 前缀、主键用 `Identity(start=1)`、String 必须写长度；
2. 改动若涉及审批动作，考虑接入 `hangchat.send_card_to_ehrs` 通知；
3. 自动回显字段在内网配的是真实 API（远程核准流水号），字段名/API 以内网 `auto_fill_triggers.json` 为准；
4. 后端端口内网是 **8081**，前端 dev 端口 8000；
5. 数据库迁移脚本需同时考虑 Oracle（隐性序列，参照 `set_sequence.py`/`迁移流程.md`）；
6. 密码/密文类配置走 `crypto` 模块，不要明文进 .env。

## 五、风险与注意事项

1. **`crypto.py` 被弱化**：`get_key()` 改为固定默认密钥、忽略 `ENCRYPT_KEY` 环境变量（原实现优先环境变量）——加密强度取决于 `_DEFAULT_KEY`，建议内网评估恢复环境变量优先。
2. **`session.py` 的 `echo=True`**：SQL 全量打印，性能与日志噪音，建议内网关掉。
3. **敏感文件事件**：本次快照混入 `.env backup`（内网 DB 连接配置）与 `token_response.json`（真实 JWT），已从 git 分支剔除、原件仅存本地 `/tmp/intranet_snapshot`；内网侧建议改名/挪走，防再次带出。
4. 内网 alembic 版本与外网根目录 alembic 是两套体系，**不要交叉混用**。
5. `statistics.py` 有一处行尾空格差异等无害噪音，合并时忽略。
