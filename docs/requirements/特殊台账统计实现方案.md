## 3. 数据模型设计

### 3.1 新建模型：`SavedFilter`（保存的筛选条件）

```python
# backend/app/models/saved_filter.py

class SavedFilter(Base):
    __tablename__ = "saved_filters"

    id          = Column(Integer, primary_key=True, index=True)
    name        = Column(String(100), nullable=False)          # 视图名称
    description = Column(Text, nullable=True)                   # 描述
    created_by_id = Column(Integer, ForeignKey("users.id"), nullable=False)

    # 筛选条件（JSON 存储）
    filter_config = Column(JSON, nullable=False)
    # 结构示例见下方 3.2

    # 时间戳
    created_at = Column(DateTime(timezone=True), server_default=func.now())
    updated_at = Column(DateTime(timezone=True), onupdate=func.now())
```

### 3.2 `filter_config` JSON 结构

```json
{
  "template_ids": [1, 2],           // 选中的模板ID列表，空数组=全部
  "system_filters": {
    "status": ["active"],           // 台账状态
    "approval_status": ["approved"],// 审批状态
    "team_ids": [1, 2],            // 团队ID列表
    "created_by_ids": [3],         // 创建人ID列表
    "created_at_range": ["2026-01-01", "2026-05-27"],  // 创建时间范围
    "updated_at_range": null        // 更新时间范围
  },
  "field_filters": {
    "字段名1": {
      "operator": "contains",       // 操作符：contains/equals/gte/lte/between/in
      "value": "关键词"
    },
    "字段名2": {
      "operator": "between",
      "value": [100, 500]
    }
  },
  "keyword": "",                     // 全局模糊搜索关键词
  "columns": ["name", "status", "字段名1"]  // 表格显示的列
}
```

### 3.3 数据库迁移

需要新建 `saved_filters` 表。SQL：

```sql
-- Oracle 生产环境
CREATE TABLE saved_filters (
    id          NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    name        VARCHAR2(100) NOT NULL,
    description CLOB,
    created_by_id NUMBER NOT NULL,
    filter_config CLOB,  -- 存储 JSON
    created_at  TIMESTAMP WITH TIME ZONE DEFAULT SYSTIMESTAMP,
    updated_at  TIMESTAMP WITH TIME ZONE,
    CONSTRAINT fk_saved_filter_user FOREIGN KEY (created_by_id) REFERENCES users(id)
);

-- SQLite 开发环境
CREATE TABLE saved_filters (
    id          INTEGER PRIMARY KEY AUTOINCREMENT,
    name        VARCHAR(100) NOT NULL,
    description TEXT,
    created_by_id INTEGER NOT NULL,
    filter_config TEXT,  -- 存储 JSON
    created_at  DATETIME DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME,
    FOREIGN KEY (created_by_id) REFERENCES users(id)
);
```

## 4. 后端 API 设计

### 4.1 查询 API

#### `POST /api/v1/statistics/ledger-query`

多维度台账查询，支持跨模板搜索。

**请求体：**
```json
{
  "template_ids": [],          // 空=全部模板
  "system_filters": {
    "status": [],
    "approval_status": [],
    "team_ids": [],
    "created_by_ids": [],
    "created_at_range": ["2026-01-01", "2026-05-27"],
    "updated_at_range": null
  },
  "field_filters": {
    "流水号": { "operator": "contains", "value": "ABC" },
    "金额": { "operator": "between", "value": [100, 500] }
  },
  "keyword": "关键词",
  "page": 1,
  "page_size": 20,
  "sort_by": "created_at",
  "sort_order": "desc"
}
```

**响应：**
```json
{
  "items": [
    {
      "id": 1,
      "name": "台账A",
      "template_id": 1,
      "template_name": "模板X",
      "status": "active",
      "approval_status": "approved",
      "team_name": "团队A",
      "created_by_name": "张三",
      "created_at": "2026-01-15T10:30:00",
      "data": { "流水号": "ABC001", "金额": 200 }
    }
  ],
  "total": 150,
  "page": 1,
  "page_size": 20
}
```

获取指定模板的字段列表（用于动态生成筛选条件）。

**响应：**
```json

  { "name": "金额", "label": "金额", "type": "number" },
  { "name": "交易码", "label": "交易码", "type": "select", "options": ["A", "B", "C"] }

```

获取所有模板及其字段的概要信息（用于多模板查询时的提示）。

### 4.2 视图（保存的筛选条件）CRUD API

#### `GET /api/v1/saved-filters/`

获取当前用户保存的所有筛选条件列表。

**响应：**
```json

  {
    "id": 1,
    "name": "本月已完成台账",
    "description": "查看本月所有已完成的台账",
```

保存筛选条件。

**请求体：**
```json
{
  "name": "本月已完成台账",
  "description": "查看本月所有已完成的台账",
```

更新已保存的筛选条件。

#### `DELETE /api/v1/saved-filters/{filter_id}`

### 5.3 查询服务核心逻辑

`statistics_service.py` 中的查询方法：

```
def query_ledgers(db, query_params) -> PaginatedResult:
    1. 基础查询: SELECT * FROM ledgers
    2. 模板筛选: WHERE template_id IN (template_ids)
    3. 系统字段筛选: WHERE status IN (...) / team_id IN (...) / created_at BETWEEN ...
    4. 全局关键词: WHERE name ILIKE '%keyword%'
    5. 自定义字段筛选（最难的部分）:
       - SQLite: json_extract(data, '$.字段名') LIKE '%value%'
       - Oracle: 看数据库中 JSON 的存储方式，可能用 JSON_VALUE 或 substr + instr
    6. 分页排序
    7. 预加载关联数据（template、team、creator）
```

### 5.4 JSON 查询兼容性方案

| 数据库 | 文本模糊匹配 | 数字范围 | 日期范围 |
|--------|-------------|---------|---------|
| SQLite | `json_extract(data, '$.field') LIKE '%val%'` | `CAST(json_extract(data, '$.field') AS REAL) BETWEEN 100 AND 500` | `json_extract(data, '$.field') BETWEEN '2026-01-01' AND '2026-12-31'` |
| Oracle | `JSON_VALUE(data, '$.field') LIKE '%val%'` 或回退到 `dbms_lob.substr` | `to_number(JSON_VALUE(data, '$.field')) BETWEEN 100 AND 500` | 日期字段比较 |

> **注意**：Oracle 的 JSON 支持取决于版本（12c+ 原生支持）。如果生产 Oracle 版本较老，data 字段在 Oracle 中实际存储为 CLOB，需要用 `dbms_lob.substr` 或注册自定义函数来查询。这部分需要根据实际 Oracle 版本调整。

## 9. 风险与注意事项

### 9.1 Oracle JSON 查询兼容性
- **风险**：不同 Oracle 版本 JSON 支持差异大
- **应对**：在 Step 3 实现时先确认生产 Oracle 版本，必要时使用 CLOB + 字符串函数替代原生 JSON 查询

### 9.2 大数据量性能
- **风险**：台账量大时 JSON 字段查询较慢
- **应对**：分页查询，JSON 查询条件不宜过多；后续可考虑对 `field_values` 表建索引

### 9.3 多模板查询时字段冲突
- **风险**：不同模板可能有同名字段但类型不同
- **应对**：多模板模式下只显示系统字段列，不显示自定义字段列；单模板模式才显示字段级筛选
