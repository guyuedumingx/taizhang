# 台账导入功能测试用例

**版本**: v2.3
**日期**: 2026-09-14
**关联文档**: [台账导入功能方案_V2.md](docs/requirements/台账导入功能方案_V2.md)
**EHR 号格式**: **7 位纯数字**(如 `1000001`),与 [user.py:11](backend/app/models/user.py#L11) 的 `ehr_id` 注释一致
**v2.3 变更**: ① 问题清单改为**按行分组展示**(不再按类型分 Tab);② 导入落库状态 `active` → **`completed`**(导入即终态,与审批通过对齐);③ 导入历史批次详情状态列显示**中文**;④ 角色管理权限列表补「导入台账」「统计分析」;⑤ 新增全场景测试 Excel([docs/test-data/导入测试_全场景.xlsx](docs/test-data/导入测试_全场景.xlsx))

## 第 0 部分:测试前准备(一次性)

| # | 步骤 | 说明 |
|---|------|------|
| P1 | 跑迁移脚本 | `python backend/scripts/migrate_ledger_import_fields.py`,预期输出两个字段已添加 |
| P2 | 启动后端 + 前端 | 后端 `uvicorn app.main:app --reload`,前端 `npm run dev` |
| P3 | 准备测试数据 | 用 admin 登录,确保系统里有:① 一个台账模板(如「测试导入」,含流水号等字段);② 至少两个团队;③ 至少两个用户,**EHR 号分别为 7 位纯数字**(如 `1000002`、`1000003`) |
| P4 | 给 admin 角色确认权限 | 管理端确认 `ledger:import` 已赋给 admin/manager 角色(本次已在 casbin_rule 预置) |

> 如果系统里还没有配置好的模板,可以先用「模板管理 → 新建模板」建一个,字段建议:`流水号`(input,必填)、`核准员姓名`(input,必填)、`交易码`(input,必填)、`备注`(textarea,选填)。同时把 [ledger_import_config.json](backend/ledger_import_config.json) 里 `template_name` 改成与该模板名一致,然后调一次 `POST /ledgers/import-configs/reload` 或重启后端。

## 第 1 部分:权限控制

### TC-01 普通用户看不到导入入口
1. 用一个**没有** `ledger:import` 权限的账号登录(或临时把某角色的该权限点去掉)
2. 进入「台账管理 → 台账列表」

**预期**:右上角**没有**「导入」按钮;左侧菜单「台账管理」下**没有**「台账导入」「导入历史」子项。

### TC-02 无权限用户直接访问 URL 被拦截
1. 仍以无权限账号登录
2. 直接在浏览器地址栏输入 `/dashboard/ledgers/import`

**预期**:前端 `useEffect` 检测到无权限,弹出「没有台账导入权限」警告并跳回台账列表。即使绕过前端,直接调 `GET /ledgers/import-configs` 也应返回 **403**。

### TC-03 有权限用户能看到完整入口
1. 用 admin(或有 `ledger:import` 的角色)登录
2. 进入台账列表

**预期**:右上角有「导入」按钮;左侧菜单「台账管理」展开后有「台账列表 / 台账导入 / 导入历史」三项。

## 第 2 部分:模板下载(Step 1)

### TC-04 下载导入模板
1. 台账列表点「导入」→ 进入导入向导,当前在第 1 步「选择模板」
2. 模板下拉选择一个模板(如「测试导入」)
3. 点「下载导入模板」

**预期**:浏览器下载一个 xlsx。打开检查:
- Sheet 1「填表说明」:有导入流程 4 步说明 + 字段填写格式表(字段名/是否必填/格式要求)
- Sheet 2(模板名):第 1 行表头与模板字段一致;第 2 行有「必填; 文本」等提示;第 3 行是灰色斜体示例,最后一列标注「示例行,请删除后从下一行开始填写」
- 若模板含 select 类型字段,对应列点单元格应有下拉箭头

### TC-05 不选模板时的按钮状态
1. 在第 1 步不选任何模板

**预期**:「下载导入模板」和「下一步」按钮均为**禁用**(灰色)。

## 第 3 部分:预校验(Step 2)

> 以下用例中的「柜员号」列请填 **7 位纯数字**。若填 `E1001` 这类带字母的格式,会命中 TC-10 的格式错误分支。
>
> **v2.3 起问题清单为「按行分组」展示**:不再按类型分 Tab,每行一条记录,行内平铺该行所有问题明细(`字段 — 原因(原始值: xx)`);表头级问题(未知列/缺列)显示在清单上方的 ⚠️ banner 里。

### TC-06 正常流程:全合法数据
1. 下载模板后,在 Sheet 2 第 4 行起填入 3~5 行合法数据(流水号唯一、柜员号填存在的 `1000002`/`1000003`、组别填存在的团队名)
2. 保存文件,回到向导点「下一步:上传文件」
3. 拖拽/点击上传该文件 → 点「开始校验」

**预期**:进入第 3 步校验报告:
- 4 张统计卡片:总行数 = N,可导入 = N,问题行 = 0
- 问题行清单显示「无问题行 ✓」
- 无表头问题 banner
- 「确认导入 N 条」按钮可用

### TC-06a 表头级问题 banner
1. 下载模板后,在 Sheet 2 表头**手动加一列**「多余列」(模板里没有的字段)
2. 填 1 行合法数据,上传 → 开始校验

**预期**:
- 清单上方出现黄底 banner「⚠️ 表头问题(1)」,内容「多余列 — 存在未知列(将被忽略)」
- 数据行本身正常可导入(未知列不影响行校验)

### TC-06b 删除示例行后导入(2026-09-15 数据丢失回归)
> 回归 bug:模板示例行标注「示例行,请删除后从下一行开始填写」,用户照做删除后,旧解析器盲跳前 3 行,会把**首条数据静默吞掉**(总行数少 1,无任何提示)。已修复为按「示例行」标记智能识别。

1. 下载模板,按说明**删除示例行**(第 3 行),从第 3 行起填入 3 行合法数据
2. 上传 → 开始校验

**预期**:
- **总行数 = 3**(不少行)
- 3 行全部可导入,问题行 0
- 问题行清单中若某行有问题,行号与 Excel 实际行号一致(如数据在第 3 行报「第 3 行」)

### TC-07 必填缺失
1. 构造一行「流水号」为空的 Excel
2. 上传 → 开始校验

**预期**:问题行清单中该行显示「第 X 行 · 共 1 个问题:流水号 — 必填字段为空(原始值: 空)」;可导入数 = 总行数 − 1;该行不进入可导入。

### TC-08 文件内重复
1. 构造两行**流水号相同**的 Excel
2. 上传 → 开始校验

**预期**:问题行清单中第二行报「流水号 — 与文件内第 X 行重复」;第一行正常可导入。

### TC-09 与库内已有台账重复
1. 先成功导入一批(拿到流水号 TSB101 等)
2. 再构造一个含**相同流水号**的 Excel
3. 上传 → 开始校验

**预期**:问题行清单显示「流水号 — 与库内已有台账 #ID 重复」(ID 是第一次导入生成的台账 ID)。这是验证库内去重的关键用例。

### TC-10 柜员号格式错误 / 不存在
1. 构造一行柜员号填 `E1001`(格式错误,带字母),另一行填 `9999999`(格式合法但系统中不存在)
2. 上传 → 开始校验

**预期**:两行都进问题行清单,原因分别为:
- `E1001` 报「柜员号 — EHR 号格式错误,应为 7 位数字(如 1000001)」
- `9999999` 报「柜员号 — EHR 号 9999999 不存在或未登记」(格式通过但反查 `users.ehr_id` 失败)

### TC-11 组别(团队)不存在
1. 构造一行组别填「不存在的团队」
2. 上传 → 开始校验

**预期**:问题行清单该行显示「组别 — 团队不存在,无法匹配(原始值: 不存在的团队)」。
**补充(兜底 + 提示 banner,2026-09-15)**:回到第 1 步,在「所属团队」下拉里选一个真实团队作为兜底,重新上传同一文件 → 预期:
- 该行变为**可导入**(组别兜底生效,团队问题不再报)
- 校验报告出现橙色 banner:「🛟 已启用团队兜底:N 行组别无法识别,已归入「所选团队名」」——兜底不再静默
- 接口返回 `fallback_notice` 字段携带同文案;未选兜底或全部组别可解析时该字段为 null

### TC-12 问题混合场景汇总(可用 [导入测试_全场景.xlsx](docs/test-data/导入测试_全场景.xlsx) 直接测)
1. 上传「导入测试_全场景.xlsx」(8 行:正常 2 + 缺必填 1 + 一行两错 1 + 文件内重复 1 + 柜员号格式错 1 + 柜员号不存在 1 + 团队不存在 1,另含 1 个未知列)
2. 上传 → 开始校验

**预期**:
- 4 张统计卡片:**总行数 8,可导入 2,问题行 6**(共 7 条明细,第 7 行有 2 条)
- ⚠️ 表头问题 banner:「多余列 — 存在未知列(将被忽略)」
- 问题行清单按行号升序排列,每行标题「第 N 行 · 共 X 个问题」,行内平铺全部明细
- 问题行之间不互相干扰(如「缺必填」行不会同时报重复)

### TC-12a 一行多字段错误的「问题行」去重计数(回归)
> 回归 v2.1 发现的 bug:一行若同时有多个单元格错误,旧版本 `问题行 = issues.length`,会被算成多行。

1. 构造一个文件:正常 1 行 + **同一行触发 2 类错误**(如「金额填 abc」+「组别填不存在的团队」)+ 单独缺必填 1 行(共 3 行)
2. 上传 → 开始校验

**预期**:
- 4 张统计卡片:**总行数 3,可导入 1,问题行 2**(注意:第 2 行虽然有 2 条 issue,但按 row 去重后只算 1 行)
- Toast 提示同步显示「问题 2 行」
- 问题行清单中该行标题为「第 X 行 · 共 2 个问题」,两条明细**同行平铺**(用户一次改完,无需跨 Tab)
- 接口返回 `ImportValidationReport.problem_rows = 2`、`issues.length = 3`

### TC-13 行数超限
1. 构造超过 5000 行的文件(可脚本生成)

**预期**:点「开始校验」直接报错「总行数 XXXX 超过硬上限 5000,请拆分文件后分批导入」(400)。

## 第 4 部分:确认导入(Step 3)

### TC-14 正常导入 + 双写验证
1. 用 TC-06 的文件,点「确认导入 N 条」
2. 等进度完成,进入第 4 步结果页

**预期**:
- 显示「导入完成:成功 N 条,失败 0 条」+ 批次号 + 用时
- 到数据库(或台账详情)抽查一条:
  - `status = completed`、`approval_status = approved`
  - `created_by_id` = 柜员号反查的用户 ID(填 `1000002` 的行 → 对应用户)
  - `imported_by_id` = 你当前登录的导入者 ID
  - `import_batch_id` = 结果页显示的批次号
- 台账列表里能搜到这批数据

### TC-14a 导入台账状态为「已完成」(v2.3 回归)
> 回归点:导入落库 `status` 从 `active` 改为 `completed`,消除「处理中/已批准」语义矛盾。

1. 完成 TC-14 导入后,在台账列表/详情查看该批台账

**预期**:
- 状态 Tag 显示绿色**「已完成」**(不再是蓝色「处理中」)
- 审批状态 Tag 显示「已批准」,两者并排语义一致
- 详情页**不显示**「审批」按钮(导入即终态,无工作流实例,预期行为)

### TC-15 导入后不可编辑/删除
1. 导入完成后,在台账列表找到导入的台账,点「编辑」/「删除」

**预期**:按现有业务规则,`completed` 状态的台账不允许编辑和删除(沿用 `update_ledger`/`delete_ledger` 的限制,active/completed 行为一致)。这正是需求里「导入即终态」的效果。

### TC-16 重复导入同一文件
1. 对刚导入成功的**同一文件**再跑一次「上传 → 校验 → 确认导入」

**预期**:校验阶段就全部报「与库内已有台账 #ID 重复」,可导入 0,「确认导入」按钮禁用。**不会**产生重复数据。

### TC-17 validate 与 commit 之间文件被替换
1. 上传文件 A 并完成预校验(看到可导入 N 条)
2. **不点确认**,回到上传步骤换文件 B(数据不同)再上传
3. 点「开始校验」→ 再点「确认导入」

**预期**:导入的是文件 B 的二次校验结果(服务端重新解析,以实时结果为准),不会出现「预览是 A、落库是 B」的不一致。

## 第 5 部分:导入历史

### TC-18 历史列表
1. 导入成功后,结果页点「查看导入历史」(或左侧菜单「导入历史」)

**预期**:列表显示刚才的批次:批次号、模板名、导入者姓名、导入时间、总行数、成功数(绿色 Tag)、失败数、文件名。操作列有「详情」,失败数 > 0 时还有「失败清单」按钮。

### TC-19 批次详情(含状态中文化 v2.3)
1. 在历史列表点某批次的「详情」

**预期**:显示批次元数据(Descriptions)+ 成功/失败/总行数 3 张卡片 + 「本批次台账」表格;表格里每条台账可点「查看」跳到台账详情。
**v2.3 状态中文化**:「本批次台账」表格的状态列显示**中文 Tag**:绿色「已完成」、审批状态列绿色「已批准」——不再显示英文 `completed`/`approved`,与台账管理模块一致(含颜色)。

### TC-20 失败清单下载
1. 构造含失败行的文件(复用 TC-12 的文件,把可导入行删掉只留问题行——注意:全失败的文件可导入 0,确认按钮禁用,所以至少留 1 行正常)
2. 导入成功(部分行失败)→ 到历史列表点该批次的「失败清单」

**预期**:下载的 xlsx 含「批次号 / 行号 / 字段 / 原始值 / 失败原因」列,失败行信息完整。
**已知边界**:当前版本「预校验阶段被跳过的问题行」只出现在校验报告里,commit 的 `failed_items` 只记录**写入阶段**失败(如数据库异常),所以正常校验拦截的行不会出现在失败清单 xlsx 中——这是 v1 简化设计的已知限制,如需要可以后续增强。

### TC-21 多批次聚合
1. 用不同文件连续导入 2~3 批

**预期**:历史列表每批一行,按导入时间倒序,分页正常(>20 批时翻页)。

## 已知问题(测试时如遇到请知悉)

1. **清洗试跑是空实现**:「可自动清洗」区域恒为空,等清洗层(field_normalizers)落地后才有内容——这是方案里预留的降级,不是 bug。
2. **「未知列」警告**:如果你手工在模板 Excel 里加了模板外的列,校验报告会在表头 banner 显示「存在未知列(将被忽略)」。**正式使用时,柜员号/组别应是模板的真实字段**,通过 `identity_mapping` 配置映射,就不会有这个警告。
3. ~~权限管理页硬编码列表漏 `ledger:import`~~ **已于 v2.3 修复**(见 TC-23):[PermissionGroups.ts](frontend/src/utils/PermissionGroups.ts) 两个列表均已补「导入台账」,并顺带补齐了同样遗漏的「统计分析」。
4. **生产部署是 Oracle 时**,迁移脚本会**打印 SQL 让 DBA 手动执行**,不会自动 ALTER。
